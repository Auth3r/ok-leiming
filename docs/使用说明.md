# 镭闪自动化 Beta 7 使用说明

本说明面向 `v1.0.0-beta.7` 预发布版。此前 Beta 6 包不含本次更新器，需首次手动安装新包；新包是否已发布，以本项目 Releases 为准。核对窗口构建号、`release-manifest.json` 和包内“更新公告.md”，不能只凭版本标题判断源码。

这是 Windows x64 预发布测试版，跨电脑和最终包游戏验收仍有未验证项。请先检查设置，再手动开始任务。模组及扫荡可能消耗游戏材料；软件打开后不会直接执行游戏操作。

## 下载、解压、启动

1. 取得 `Leiming-Automation-v1.0.0-beta.7-win-x64.zip` 便携包。GitHub 页面上的 Source code 压缩包不是可运行安装包。
2. 将 ZIP **完整解压**到自己能写入的普通目录，例如桌面或个人文档中的新文件夹。不要在压缩包预览中直接启动，也不要只复制 EXE。
3. 双击 `Leiming-Automation.exe`。无需安装 Python、pip 或开发环境。
4. 确认主窗口显示 `v1.0.0-beta.7`，提交号与同目录 `release-manifest.json` 一致。保留同目录的运行依赖、模型、模板和图标文件。

Beta 7 发布页为 https://github.com/Auth3r/ok-leiming/releases/tag/v1.0.0-beta.7；这是公开仓库，下载不需要 GitHub Token；同时取得同一 ZIP 的 SHA256 校验文件，范围见 PUBLICATION_CHECK.md。

包内 `licenses` 保存第三方许可证、版权通知及必要的对应源码。普通运行无需打开源码；转交安装包时请保留整个目录。接收人的开源许可权利以各组件原始条款为准。详细说明见 `licenses/THIRD-PARTY-NOTICES.md`。

## 首次配置

1. 手动启动并登录游戏，先进入指挥室等已知页面。软件不负责登录账号或输入密码。
2. 打开软件的“截图方式”，检查“游戏连接与问题报告”中的连接状态与游戏预览。游戏进程为 `Warp Knights.exe`；窗口标题默认留空。未连接时先点刷新，确认选中的是实际游戏窗口。
3. 优先使用 **1280×720 窗口化**；保留3840×2160无边框路径。Windows缩放按当前窗口读取，无须固定为150%。软件“游戏分辨率”默认自动识别。桌面分辨率与游戏客户区尺寸分别检测，无须把4K桌面改成720P。本次各模式的实机验证范围见验收报告。
4. 截图需能依据实际窗口和客户区边界确认完整、未缩放的映射。窗口尺寸、DPI或截图来源不可信时，程序会在输入前停止并说明原因。软件自动读取窗口位置，不需填写坐标。改变窗口或显示设置后，先停止任务并重新检查预览。
5. 在“设置 → 日常任务”选择日常项目，首次生成的七项日常开关全部开启，已有保存选择保持不变。暗涌次数也可在“截图方式 → 暗涌扫荡设置”保存，0 表示跳过。制作数量及肉鸽循环次数首次建议保持 1，并检查每个模块的材料消耗。
6. 在“模组制作”检查制作配置、数量及属性刷新方式；在“设置 → Roguelike”检查肉鸽循环次数和悬浮窗开关。

目录可写时，配置、日志和缓存保存在便携目录内。目录只读时，自动使用当前Windows用户的本地应用数据目录 `Leiming-Automation/portable-安装位置摘要`，重启继续使用同一位置。资源仍从解压目录加载。中文目录不需要映射盘符。不要把自己的配置目录作为安装包发送给别人。

若窗口身份、分辨率、权限或截图不符合要求，软件会停止输入并显示原因。按提示检查真实窗口和程序权限，再继续；不要降低识别阈值来强行绕过。运行期间保持游戏可见，不要最小化或移动、缩放游戏窗口。

## 开始、暂停、继续、停止

- **开始**：检查配置后，在对应任务入口点击开始。单项用于分别执行某项日常；完整日常路线按已保存的开关运行。
- **暂停／继续**：点击当前任务控件，或按 F7。暂停后不发送新的游戏输入；继续会重新读取当前页面。已经发出的动作不会撤销。
- **停止**：点击停止或按 F8，结束当前任务及后续队列。停止后需要从对应入口重新启动；“继续”不能把已停止的任务变回运行中。
- **日常失败后恢复**：再次开始时按当前页面核对任务；过期或不适用的检查点保留为历史证据，不阻断整条日常。能够识别的奖励和任务页面会通过原有返回流程恢复。无法确认的消耗只影响相关项目，不重复提交，也不算成功。
- **模组中途恢复**：游戏仍在本件制作页面时，使用“继续当前模组”。无法证明的旧历史保留为未知；完成数未知时只继续当前一件。若提示不可逆确认结果不明，先核对现场，不要反复点击开始或清除记录绕过保护。
- **肉鸽中途恢复**：暂停时使用当前控件继续；720P使用原生运行面板，按当前状态操作。停止后能否接续取决于现场及已有记录，未知状态不要反复重启。

日常默认可以在模块间临时归还前台，执行模块时仍会接管游戏。请以软件显示的当前状态为准；切回助手可能触发暂停，继续后会重新识别，不会沿用旧页面位置。

## 日常任务

在“设置 → 日常任务”选择需要执行的项目，再在日常任务卡中点击开始。可单独运行黑盾领取、派遣、理财基金、暗涌 04-3、干火 ST-7、猎金 ER-2及每日奖励。

暗涌扫荡会消耗体力，按保存的次数执行，不自动补体力。次数不足、库存满、未知弹层或关键识别失败时会停止或在安全返回后跳过。模组库存需要自己清理，软件不会自动拆解。

普通派遣按当前界面顺序逐人选择，最多三名并核对实际槽位和委托条件，不由助手另行按战力重排。明确要求四人同战术时，固定筛选乌斯怀亚，按从左至右、从上至下选择界面前四名并逐人核对；职业种类数2沿用普通规则，不套用四人同战术策略。

完成后检查每项状态。`SKIPPED` 是跳过，`PARTIAL` 是部分完成；整次流程结束不等于所有项目都成功领取或执行。

## 模组自动化

在“模组制作”的“制作配置”选择军工、一致或先攻，顶部策略公告会随选择变化。“旧地联合”保留兼容入口，但当前游戏环境无法正常制作，不作为本赛季可用制作目标。

1. 检查制作数量、属性刷新方式、人数门槛以及火力攻击奖励任务优先设置。
2. 配队由使用者手动完成。“准备”入口只处理胚子和蓝图准备并检查队伍，完成后停止，不启动实验；程序不会修改军工／一致的队员。
3. 循环制作入口会启动研发并可能消耗制作与刷新材料；确认愿意承担这些消耗后再开始。
4. 军工／一致按预设规则优先本地技能。先攻先尝试完美目标，目标无法完成或刷新后缺少目标时，可转为狗粮模式；状态显示在公告／记录中。
5. 四种配置都要求“声东击西＋好整以暇”因子组合，组合无法取得会快速结束本件。正常完成与快速结束都计入本轮完成数。

策略不是完美结果保证。先攻后半程随机组合、未来技能机会、超频、未知区域等特殊路径仍待进一步验证；遇到安全停止请查看原因，不要追加材料强行继续。

“显示 / 隐藏制作记录”控制悬浮窗。“调整制作记录浮窗”可进入拖动模式，调整完后点击“完成调整”；也可重置位置或调透明度。调整应在没有制作任务运行时进行。

## 肉鸽功能

720P使用 **720P 肉鸽（原生 WGC）** 面板的开始／暂停／继续／停止控件。4K使用既有任务入口；本轮恢复发行包对4K的兼容，但新包4K游戏流程尚需实机复核。

循环次数使用“设置 → Roguelike”的循环次数和悬浮窗开关，下次开始生效。不要同时运行日常、模组或另一种肉鸽模式。

一轮沿用第二层悬赏后结算的既定刷取路线，不表示五层全通。未支持页面、登录、权限、稀缺资源确认等异常会停止或安全暂停，并显示现场。连续多轮和全部随机事件未完整实机验收。

## 遇到问题

1. 先按 F8 或点击停止，保留游戏现场。不要为复现错误重新消耗材料。
2. 记录软件版本、游戏客户区分辨率、Windows 缩放、所用功能及最后一条错误提示。
3. 在“截图方式 → 游戏连接与问题报告”点击“生成问题报告”。报告保存在便携目录的 `reports` 文件夹，只在本机生成，不会自动上传。
4. 检查报告后，再通过开发者指定的私密渠道发送。报告可能包含窗口标题、任务配置、日志和游戏截图；发送前避免包含账号、聊天、昵称等不必要个人信息。只提供定位问题所需证据，必要时对副本遮挡个人内容，自己保留原始日志。

框架文字日志每份最多5 MiB，保留3份轮转备份。512 MiB是日志清理目标，达到后自动清理最旧普通日志和截图；保留近期、故障和恢复账本证据。维护最多每分钟一次，清理失败或全部为保留证据时可能超过目标，但不会因此停止输入或停止记录。文字日志被占用时切换新分段。问题报告最多收集24 MiB日志，只在本机生成。

原始运行日志在 `logs` 文件夹，每次运行有独立记录。`result.json` 和 `events.jsonl` 记录结果和过程；`FAILED` 图片为错误现场。肉鸽 720P 的日志在 `logs/roguelike-720p` 下。不要在制作尚未完成时删除日志或恢复记录，可能影响同件接续。

## 手动更新与保留配置

Beta 7 可以在“关于”检查本项目已发布的版本；Beta 默认包含测试版本，草稿和低版本不会安装。公开更新源为 `Auth3r/ok-leiming`，默认匿名访问，普通用户无需 Token；程序不保存凭据或读取开发者 Git 登录。权限、网络或数据错误会明确提示，不妨碍正常使用。

存在更高合格版本时，先停止所有任务，再点击更新。程序校验下载与包内文件，退出后由独立安装器保留个人数据、替换和重启；新版启动失败时恢复旧版，旧安装完整保留在旁侧 `.backup-` 目录。只读目录、文件占用或空间不足不会强行覆盖原程序，可继续使用下述手动流程。Beta 7 发布时尚无更高已发布版本，真实线上升级保留为未来独立验收项。

手动包从[本项目 Releases](https://github.com/Auth3r/ok-leiming/releases)取得，并核对同名 SHA256。旧 Beta 6 的 Launcher 错误不能在原包内自动修复，需先取得首个包含新更新器的完整包。原创部分 MIT 见包内 `LICENSE`，适用范围见 `PROJECT-NOTICES.txt`，第三方材料保留在 `licenses`。

**推荐在没有进行中的制作时解压到独立新目录，保留旧版本直到新版本启动和配置核对成功。** 不要将新版 ZIP 直接覆盖解压到正在使用的旧目录。停止助手不等于游戏内当前实验已结束。

1. 停止任务，关闭旧版软件，备份整个旧目录。
2. 将新版 ZIP 解压到一个新的可写目录；在新程序首次启动前，一并复制旧版根目录的 `settings.json`、`config_version.json`、完整 `configs` 文件夹及已有的 `config-backups` 文件夹。已使用新版配置的旧目录不能漏复制 `config_version.json`；只有确实没有版本标记的早期旧配置才略过该文件，不要自行新建。配置只能复制自己的，不能复制开发者的配置。
3. 保留旧目录及自己的 `logs` 备份，不默认迁入新版。旧日志包含同件账本和现场证据，跨版本／跨目录接续尚未完整验收；有未完成模组时先保留现场并由开发者核对。不要复制 `.venv`、旧 EXE、旧运行依赖或模板来覆盖新版文件。
4. 启动新版，核对游戏窗口、分辨率、日常开关、扫荡次数、制作配置／数量／刷新方式、肉鸽参数和个人偏好，再手动运行任务。

已有版本化配置按原字段保留；旧结构会在任务加载前按既有机制迁移，迁移写入前备份至 `config-backups/stage1-v0`。旧文件中的有效值冲突时会报告来源并停止，不会猜选或无提示覆盖。迁移失败请保留旧目录及备份，提供错误提示，由开发者核对后修正；不要直接删配置来解决。

若仅缺少 `config_version.json`，程序会核验现有完整配置结构并自动补回版本标记，原配置内容保持不变。配置本身缺失或冲突时保留文件并说明具体问题。

使用全新目录且不复制任何旧配置时，软件生成默认配置。换电脑时游戏窗口设备信息或悬浮窗位置可能需要重新选择／调整，仍应先检查预览，再开始操作。

## 本版验证边界

已有主要验证环境为720P窗口化和150% DPI，并保留既有4K实现。2026-10-22 只准备候选及无消耗验证，本次实际结果见对应 Release 草稿与包旁记录；独立解压启动不等于跨电脑通过。2026-10-23 仍待第二台电脑、最终候选包游戏流程及四人同战术专项验收。不同DPI的接口测试不能替代各电脑的实机验收，日常、模组和肉鸽随机／恢复路径仍有未覆盖项。

本版仍为 Beta，实际游戏验收应按当次授权范围执行，不继承开发者此前的材料消耗额度。默认制作和肉鸽循环数量均为1，首次七项日常开关全部开启；任务仍需手动开始，已有保存选择保持不变。每次开始前核对当前任务、数量和刷新设置。部分随机流程尚无完整实机覆盖，不保证每件获得完美模组。
